## 变更记录

- **2026-11-28 · PRD 01 二次改版（实现后用户反馈）**：原方案「粘贴文本 + 估算 token + 单次/月成本」被判定为伪精确——用户调用前并不知道输出长度，且重心应是横向比价。已改为 **LLM Price Compare / 模型價格比較器**：
  1. 模型数据源从 11 个扩到 20 个（附录 A 全部型号，促销价带常规价兜底）。
  2. 单选下拉改多选，20 个模型并排卡片对比。
  3. 顶部高亮当前最低费用模型；按 **3:1 加权**（3 份输入 + 1 份输出，行业常见口径，界面明示）得出单一可比数字。
  4. 删除文本输入、输出、每日呼叫次数三个控件；保留汇率框（用户选择「加汇率框统一换算」），CNY 按汇率折算 USD 后参与排名，USD 价格不变。
  5. 工具不再读写 URL fragment，不再估算 token；`estimate.ts` / `state.ts` 已删除。
  下方 PRD 01 原文保留作历史记录，以本节为准。

## 三、逐份 PRD

### PRD 01 · Token 成本计算器 / Token Cost Calculator

**领域**：数据｜**路由**：`/tools/token-cost-calculator`

**趋势依据**【官方】：Google Cloud《ROI of AI 2026》报告（数据来自 Google Trends 全球）显示，2026 上半年 token efficiency 相关搜索量增长 335%。第三方周度快照中 token counter 也曾 +34.8%，但 11-27 回落 -20.6%，仅作辅助参考。

**定位**：给开发者和内容创作者用的 LLM 用量成本预估工具——粘贴文本，立刻看到 token 数与对应模型费用。

**功能规格**
- 粘贴或输入文本，实时估算 token 数（中英文分别标注估算系数）
- 模型下拉：GPT / Claude / Gemini / 国产主流模型；单价表见附录 A.1，**默认值可覆盖**，必须标注型号 + 数据日期 + 促销到期日（如 Gemini 4 Argon 的 $2/$10 仅至 11-30）
- 输出单次成本、按调用量（日/月）推算的总成本
- 上下文窗口占用进度条，超出时警示
- 一键复制估算结果为文本

**UI 结构**：左侧大文本域 + 模型选择卡；右侧 sticky 结果面板（token 数大号数字 → 成本卡片 → 窗口占用条 → 复制按钮）。浅色雾白星金主题，深色模式同站点变量。

**技术方案**
- `src/features/token-cost-calculator/lib/estimate.ts`：纯函数 token 估算，标注「估算值，非精确 tokenizer」
- `src/features/token-cost-calculator/lib/pricing.ts`：模型价格表 + 版本日期
- 双路由 `src/app/tools/.../page.tsx` 与 `src/app/[locale]/tools/.../page.tsx`
- 输入状态写入 URL fragment（ADR-0002），无 localStorage
- 不引入第三方 tokenizer 依赖，保持首屏轻量

**SEO**：英文 `token counter` / `llm cost calculator` / `token cost estimator`；中文 `token 计算器` / `大模型成本估算`。标题「Token Cost Calculator — StarRudder」，描述强调 local & private。

**验收标准**
- [ ] 中文 500 字、英文 500 词分别估算，结果在合理区间
- [ ] 切换模型后成本实时重算
- [ ] 价格表注明更新日期与「仅供参考」
- [ ] URL fragment 可还原输入
- [ ] 页面不发任何用户数据请求

**领域**：金融｜**路由**：`/tools/ai-roi-calculator`

**SEO**：`ai roi calculator` / `ai cost savings calculator` / `AI 投资回报计算器`。

### PRD 03 · 图片转文字 / Image to Text (OCR)

**领域**：行政｜**路由**：`/tools/image-to-text`

**趋势依据**【官方】：Google 官方博客 2026-05-19 披露，美国超过 1/6 搜索使用语音或图片，图片搜索月环比增长超 40%。

**定位**：截图/照片本地 OCR——拖入图片，直接拿到可复制文字，图片不离开设备。

**功能规格**
- 拖放或选择 PNG / JPG / WebP，最大 10MB
- 浏览器内 OCR（Tesseract.js，WASM 本地运行），支持中英
- 识别中显示进度；输出文本区可编辑、可复制、可下载 txt
- 一键清空，图片仅存内存

**UI 结构**：居中拖放区 → 识别进度条 → 文本结果卡（等宽字体）+ 操作按钮组。空态给出「图片只在本机处理」的安心提示。

**技术方案**
- Tesseract.js 动态 `import()` 按需加载，避免拖慢首屏
- WASM / 语言包本地打包到 `public/`，**不依赖 CDN**，保证「不发用户数据请求」的承诺
- 首次加载体积提示（约数 MB）
- 只在内存中持有 File / Blob，组件卸载即释放

**SEO**：`image to text` / `screenshot ocr` / `图片转文字` / `截图识别文字`。

**验收标准**
- [ ] 中文截图与英文截图均能识别
- [ ] 网络面板确认图像未被上传（仅加载本站 WASM 静态资源）
- [ ] 超过 10MB 给出友好提示
- [ ] 清空后内存中不再持有图片
- [ ] 移动端可拍照上传

**SEO**：`profit margin calculator` / `product pricing calculator` / `毛利率计算器`。

**验收标准**

### PRD 07 · 健康指标计算器 / Health Metrics Calculator

**领域**：医疗｜**路由**：`/tools/health-metrics-calculator`

**趋势依据**：**无强趋势信号**，本项由「补齐医疗空白领域」驱动，不宣称趋势背书。SEO 靠 BMI / BMR 等常青搜索词。

> **2026-11-28 替换评估结论：保留原方案，不替换。** 曾评估改为「体检报告指标解读器」，调研显示需求真实（79% 搜索是找指标含义/正常范围，年度体检超 5 亿人次），但存在三处硬冲突：① 合规红线（AI 不得替代医师、辅助诊疗按三类医疗器械管理）；② 红海竞争（蚂蚁阿福月活超 1500 万且免费、丁香医生、平安好医生等占据入口）；③ 中文报告 OCR 版式 + 参考范围因实验室/年龄/性别而异 + 多指标关联缺乏临床上下文，技术可信度不足。若未来要覆盖该需求，只做降级版「报告指标速查器」（单指标白话解释 + 参考范围对照 + 异常方向提示 + 强制就医引导，绝不出诊断），不整体替换。

**定位**：一组纯计算的健康参考值——不做诊断、不存数据。

**功能规格**
- BMI（含中国成人区间参考）
- 基础代谢率 BMR（Mifflin-St Jeor 公式）
- 每日建议饮水量（体重系数）
- 体脂率（美国海军公式，可选）
- 显著免责声明：仅供健康成人参考，非医疗建议

**UI 结构**：顶部表单（身高/体重/年龄/性别/活动量）→ 结果卡网格 → 底部免责声明条。

**技术方案**：`lib/health.ts` 纯函数 + 公式单元测试；常量与区间表独立；无存储。

**SEO**：`bmi calculator` / `basal metabolic rate calculator` / `BMI 计算器` / `基础代谢率计算器`。

**验收标准**
- [ ] 四项公式结果可手算核对
- [ ] 免责声明在首屏可见
- [ ] 超出合理范围（如身高 300cm）给出提示
- [ ] 不保存任何输入

**领域**：行政｜**路由**：`/tools/pdf-compressor`

- `pdf-lib` 动态 import；图片降采样 + 元数据清理
- 大文件提示与内存管理
- 文件仅内存，不发网络请求

**SEO**：`pdf compressor` / `compress pdf online` / `PDF 压缩`。

**验收标准**
- [ ] 10MB 测试 PDF 压缩后体积下降
- [ ] 压缩后文件可正常打开
- [ ] 网络面板无文件上传

## 五、费率数据更新机制（2026-11-28 决策）

> **用户决策**：脚本生成 + 同源读取；**当天已拉取过就不再拉取**（2026-11-28 补充）。
> `public/data/rates.json` 与更新脚本均已实现（`npm run rates:update`）；汇率也纳入 JSON，由脚本一并刷新。

### 5.1 为什么不违反「纯浏览器」承诺

站点承诺的是「不上传、不保存**用户数据**」。费率是站点自带的公开配置数据，与用户输入无关：工具从本站同源读取一份静态 JSON，既不请求外部 API，也不上传任何用户输入。因此不突破「纯浏览器」边界。

**缓存同理**（2026-11-28 补充）：localStorage 里只放「拉取日期 + 公开费率数据」（键 `starrudder:rates-cache`），不放任何用户输入或计算结果；用户输入仍按 ADR-0002 写入 URL fragment。这与「不保存用户数据」的承诺不冲突。

### 5.2 单一数据文件

三组费率（模型 API 价格、支付通道费率、平台佣金）合并进**一个** JSON 文件：

```
public/data/rates.json
```

结构约定（字段是设计草案，实现时可调整）：

```json
{
  "meta": {
    "updatedAt": "2026-11-28",
    "note": "公开挂牌价，以官方/签约页为准",
    "exchangeRate": 6.6544,
    "fxDate": "2026-11-27",
    "fxSource": "https://api.frankfurter.dev (ECB reference rate)"
  },
  "llmPricing": [
    {
      "vendor": "Google",
      "model": "Gemini 4 Argon",
      "inputPerM": 2,
      "outputPerM": 10,
      "currency": "USD",
      "promoUntil": "2026-11-30",
      "regularInputPerM": 4,
      "regularOutputPerM": 20,
      "source": "第三方引用官方页",
      "confidence": "medium"
    }
  ],
  "paymentFees": [
    {
      "provider": "Stripe",
      "region": "US",
      "percent": 2.9,
      "fixed": 0.30,
      "currency": "USD",
      "source": "stripe.com/us/pricing"
    }
  ],
  "platformFees": [
    {
      "platform": "Etsy",
      "type": "fixed",
      "rate": 6.5,
      "note": "交易费；另有上架费 $0.20/件"
    }
  ]
}
```

要点：
- `meta.updatedAt` 是数据新鲜度的唯一来源，UI 必须展示
- `meta.exchangeRate` / `fxDate` / `fxSource` 是汇率默认值，脚本刷新；UI 可覆盖
- 时间敏感值（促销到期、峰谷时段、涨价日）用专门字段表达，不用注释写死在文字里
- 促销价必须同时给出 `regularInputPerM` / `regularOutputPerM`，`promoUntil` 过期后自动回落到常规价，不留价格空窗
- `confidence` 标记 official / medium / low，低置信度值在 UI 上弱化显示
- 类目佣金区间、签约议价费率**不写入** JSON（因人而异），由用户在 UI 填写

### 5.3 更新脚本（已实现）

命令：`npm run rates:update`；预览不写文件：`npm run rates:update -- --dry-run`。

**上游源**（均为公开、免密钥接口，脚本运行时才访问；不进浏览器 bundle）：
- 模型价格：Models.dev `https://models.dev/api.json` —— 每百万 token 美元价与发布日期
- 汇率：Frankfurter `https://api.frankfurter.dev/v1/latest?base=USD&symbols=CNY` —— ECB 参考汇率

**刷新规则**（纯逻辑在 `scripts/update-rates-lib.mjs`，12 项单测覆盖）：
1. USD 价格按别名表对齐上游；价格变化写入 diff；即使价格未变也打上游 source，证明已核对
2. CNY 价格**不自动覆盖**——上游只有单一美元价，无法表达国内峰谷时段，保留人工值
3. 促销价与 `regularInputPerM` / `regularOutputPerM` 保留人工标注，脚本不碰
4. 上游 0/0 视为「订阅打包价」而非免费，拒绝写入
5. 新模型按厂商白名单发现，**每个厂商最多 1 个最新通用旗舰**；排除医疗/视觉/预览/lite/mini 等变体，并抑制同系列旧版本（Fable 5.1 不会顶掉已收录的 5.2）
6. 汇率写入 `meta.exchangeRate` + `fxDate` + `fxSource`；抓取失败保留旧值并告警
7. 任一上游失败都不清空已有数据；校验不通过则拒绝写文件（`validateRates`）

**2026-11-28 首次 dry-run 结果**：20 个模型中 4 个 USD 价格随上游微调（如 GPT-6.2 Astra 8/40 → 8.8/44），无新增旗舰（现有 20 个已是各白名单厂商最新），汇率 6.6544（2026-11-27）。本次未写入文件——保留附录 A 人工核对过的价格，待用户决定是否采用上游值。

**未来新模型如何进入工具**：跑 `npm run rates:update` → 审查 diff → 确认后提交生成的 JSON。工具当天首次打开读取一次并缓存，当日不再请求。

### 5.4 工具侧读取流程

1. 先读 localStorage 的 `starrudder:rates-cache`：**日期为今天** → 直接用缓存，不发请求
2. 缓存非今天或不存在 → `fetch("/data/rates.json")`（同源、GET、无用户参数），成功后写入缓存（日期 + 数据）
3. 拉取失败但缓存可用 → 用旧缓存并显示「更新失败，使用缓存费率先」提示；无缓存 → 内置精简 fallback 表 + 「使用离线默认值」提示
4. `meta.updatedAt` 超过 30 天 → 顶部显示「费率数据可能已过期，请以官方页为准」提示
5. 所有费率字段在 UI 上可编辑，覆盖 JSON 默认值（促销到期价按日期自动切换，用户可手动改）

### 5.5 涉及工具与验收补充

|---|---|

| #4 定价与利润计算器 | `platformFees` |
